# Fireflies Clone — Meeting Notes & Transcription Platform

A functional clone of the [Fireflies.ai](https://fireflies.ai) meeting assistant. Browse a
library of meetings, read **interactive transcripts** with speaker labels and timestamps,
view **AI-generated summaries, action items, and topics**, search across every transcript,
and manage meetings end-to-end — in a clean, productivity-focused UI with light/dark modes.

Real speech-to-text is intentionally out of scope (per the assignment). Transcripts are
**seeded, pasted, or uploaded** (`.txt` / `.vtt` / `.json`) and summaries are generated by a
**hybrid engine**: a deterministic offline summarizer by default, with an optional LLM upgrade
when an API key is configured.

> **Default user:** authentication is mocked — the app assumes a single logged-in user, seeded
> as *Siddharth Singh*.

## Tech Stack

| Layer | Choice | Why |
|-------|--------|-----|
| Frontend | **Next.js 14 (App Router) + TypeScript** | Modern React, file routing, server/client split |
| Styling | **Tailwind CSS** + custom shadcn-style primitives | Fast, consistent, theme-able (CSS variables) |
| Data fetching | **TanStack Query** | Caching, mutations, auto-invalidation |
| Backend | **FastAPI (Python)** | Async, Pydantic validation, auto Swagger docs |
| ORM | **SQLAlchemy 2.0** (typed) | Parameterized queries, clean relationships |
| Database | **SQLite** | Zero-config, file-based, easy to ship |
| Toasts / theme | **sonner**, **next-themes** | Notifications and dark mode |

## Features

**Core (required)**
- **Meetings library / dashboard** — cards with title, date, duration, participants; server-side
  search (title/participant), tag filter, sort (recent / oldest / title / duration), pagination.
- **Interactive transcript** — speaker labels, timestamps, **click a line to seek** the player,
  active line auto-highlights and auto-scrolls as it plays, **in-transcript search** with match
  navigation and highlighting.
- **Media player** — custom controls (play/pause, ±10s, speed), seek bar. A **virtual clock**
  drives the playhead so click-to-seek always works even if the sample audio can't load.
- **AI summary & notes** — overview, keywords, sentiment, **action items**, **topics/chapters**
  (chapters are clickable and seek the player).
- **Meeting management (CRUD)** — create via paste/upload/form, edit metadata, delete (cascades),
  full add/edit/complete/delete for action items. Everything persists.
- **Fireflies experience** — sidebar + topbar layout, modals, toasts, settings placeholders,
  "Coming Soon" stubs for live bot / integrations / team.

**Bonus (implemented)**
- 🌙 **Dark mode** · 🔎 **Global search** across all transcripts (jump straight to the line) ·
  📤 **Export** (Markdown / TXT / Print-to-PDF) · 💬 **Ask-a-question chat** grounded in the
  transcript with clickable source citations · 💭 per-segment **comments** · ✏️ **speaker rename**.

## Architecture

```
┌─────────────────────────┐        HTTPS / REST        ┌──────────────────────────┐
│  FRONTEND (Next.js)      │  ───────────────────────►  │  BACKEND (FastAPI)        │
│  TypeScript · Tailwind   │                            │  Pydantic validation      │
│  TanStack Query          │  ◄───────────────────────  │  SQLAlchemy 2.0 ORM       │
│  lib/api.ts (1 client)   │        JSON                │  Service layer            │
└─────────────────────────┘                            └────────────┬─────────────┘
                                                                     │
                                                            ┌────────▼────────┐
                                                            │  SQLite (file)  │
                                                            └─────────────────┘
```

**Backend layering (separation of concerns):**
- `routers/` — thin HTTP layer (validation, status codes, ownership checks)
- `services/` — business logic: `transcript_parser` (txt/vtt/json → segments),
  `summarizer` (offline extractive engine), `llm` (optional LLM + graceful fallback),
  `meeting_service` (assembles a meeting from parsed data)
- `models.py` — SQLAlchemy schema · `schemas.py` — Pydantic request/response contracts

**Frontend:** one typed API client (`lib/api.ts`), React Query hooks (`lib/hooks.ts`), and
composable components under `components/` (`layout/`, `meetings/`, `detail/`, `ui/`).

## Database Schema

```
users (1) ──< meetings (1) ──< participants
                     │       ──< speakers (1) ──< transcript_segments >── (speaker_id)
                     │       ──< transcript_segments (1) ──< comments
                     │       ──1 summaries
                     │       ──< action_items
                     │       ──< topics
                     └──< meeting_tags >── tags   (many-to-many)
```

Key decisions:
- **Timestamps as integer milliseconds** (`start_ms` / `end_ms`) — exact, easy to compare, and
  map directly onto the player's `currentTime` for sync (no timezone/float issues).
- **Transcript = one row per segment** (not a blob) — enables per-line seek, search-highlight,
  and per-segment comments.
- **Summary is 1:1** with a meeting; action items / topics / segments / participants are 1:many;
  tags are many:many. All children **cascade on meeting delete** (FK `ON DELETE CASCADE`, with
  SQLite `PRAGMA foreign_keys=ON` enforced at startup).
- A single default **User** models auth so real multi-user auth is a drop-in later.

Full model definitions: [`backend/app/models.py`](backend/app/models.py).

## API Overview

Interactive docs (Swagger) live at **`/docs`** when the backend is running.

| Method | Endpoint | Purpose |
|--------|----------|---------|
| `GET` | `/api/health` | Health + whether LLM is enabled |
| `GET` | `/api/me` | Current (default) user |
| `GET` | `/api/tags` | All tags (for filters) |
| `GET` | `/api/meetings` | List: `q`, `participant`, `tag`, `date_from/to`, `sort`, `page`, `page_size` |
| `POST` | `/api/meetings` | Create (form + optional pasted transcript) |
| `POST` | `/api/meetings/upload` | Create from an uploaded `.txt`/`.vtt`/`.json` file |
| `GET` | `/api/meetings/{id}` | Full detail (segments, summary, actions, topics…) |
| `PATCH` | `/api/meetings/{id}` | Edit metadata / participants / tags |
| `DELETE` | `/api/meetings/{id}` | Delete (cascades) |
| `POST` | `/api/meetings/{id}/regenerate-summary` | Regenerate (LLM if configured, else rule engine) |
| `POST` `PATCH` `DELETE` | `/api/meetings/{id}/action-items[/{itemId}]` | Action item CRUD |
| `PATCH` | `/api/meetings/{id}/speakers/{speakerId}` | Rename a speaker |
| `GET` `POST` `DELETE` | `/api/meetings/{id}/segments/{segId}/comments[/{cId}]` | Segment comments |
| `GET` | `/api/search?q=` | Global search across all transcripts |
| `POST` | `/api/meetings/{id}/chat` | Ask a question about the meeting |
| `GET` | `/api/meetings/{id}/export?format=md\|txt` | Export transcript + summary |

## Local Setup

**Prerequisites:** Python 3.11–3.12 and Node.js 18+.

### 1. Backend
```bash
cd backend
python3.12 -m venv .venv && source .venv/bin/activate   # Windows: .venv\Scripts\activate
pip install -r requirements.txt
python -m app.seed          # creates the DB and loads demo meetings
uvicorn app.main:app --reload --port 8000
```
Backend runs at http://localhost:8000 · docs at http://localhost:8000/docs

### 2. Frontend
```bash
cd frontend
npm install
cp .env.local.example .env.local     # NEXT_PUBLIC_API_URL=http://localhost:8000
npm run dev
```
App runs at http://localhost:3000

## Environment Variables

**Backend** (`backend/.env`, all optional — sensible defaults):
| Var | Default | Notes |
|-----|---------|-------|
| `DATABASE_URL` | `sqlite:///./fireflies.db` | Point at a persistent volume in prod |
| `CORS_ORIGINS` | `http://localhost:3000` | Comma-separated allowed origins |
| `MAX_UPLOAD_BYTES` | `5242880` | 5 MB upload cap |
| `LLM_PROVIDER` | `none` | `anthropic` \| `openai` \| `none` |
| `ANTHROPIC_API_KEY` / `OPENAI_API_KEY` | — | Enables real LLM summary + chat |
| `LLM_MODEL` | `claude-sonnet-5` | Model id for the chosen provider |

**Frontend** (`frontend/.env.local`):
| Var | Notes |
|-----|-------|
| `NEXT_PUBLIC_API_URL` | Base URL of the backend API |

> Without an LLM key everything still works — "Regenerate summary" and "Ask AI" fall back to a
> deterministic extractive engine, so the demo never breaks.

## Deployment

The app is deployment-agnostic (env-driven config + a backend `Dockerfile`).

- **Frontend → Vercel:** import the repo, set root to `frontend/`, add `NEXT_PUBLIC_API_URL`.
- **Backend → Render / Railway / Fly:** deploy `backend/` (Docker). **Attach a persistent disk**
  and set `DATABASE_URL` to a path on it (e.g. `sqlite:////data/app.db`) so the SQLite file
  survives redeploys. Set `CORS_ORIGINS` to the Vercel URL.

## Assumptions & Design Decisions

- **Auth is mocked** — one seeded default user; ownership checks are wired so real auth drops in.
- **Media is a placeholder** — sample audio; a virtual clock guarantees transcript sync works
  regardless of audio availability.
- **Hybrid AI** — offline-first so demos are reliable; LLM is an opt-in enhancement.
- **Timestamps auto-synthesized** for transcripts without timing (~150 wpm) so seek always works.
- **Security basics** — Pydantic validation on all input, ORM (no raw SQL), CORS allowlist,
  upload extension/size guards, no stack traces leaked to clients.
